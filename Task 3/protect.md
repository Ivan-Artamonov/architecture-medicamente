# Стратегия шифрования данных

| Данные | Необходимость защиты | Инструменты защиты |
|---|---|---|
| Персональные данные пациента <br/>В покое: профиль пациента в CRM. <br/>При передаче: портал пациента/ресепшена - CRM; CRM - внутренние сервисы | Несанкционированный доступ раскрывает личность пациента и позволяет связать ее с медицинскими сведениями | В покое: шифрование БД/диска CRM и резервных копий <br/>При передаче: TLS для сервисов и соединения с БД. <br/>Аналитика: псевдонимизация до загрузки в Data Lake. <br/>Контроль: проверка шифрования БД и хранилища |
| Контактные данные: телефон, email, адрес из расширенной анкеты <br/>В покое: CRM <br/>При передаче: портал/ресепшен - CRM | Утечка позволяет использовать контакты вне цели обслуживания | В покое: шифрование БД, документного хранилища и резервных копий<br/>При передаче: TLS  <br/>Контроль: поиск прямых контактов в аналитических выгрузках |
| Данные записи: пациент, врач, дата/время и запись на прием <br/>В покое: записи и расписания в CRM <br/>При передаче: портал пациента/ресепшена и рабочее место врача обмениваются данными с CRM | Раскрытие расписания нарушает конфиденциальность посещений и раскрывает связь пациента с конкретной услугой | В покое: шифрование БД CRM и резервных копий. <br/>При передаче: TLS  <br/>Контроль: мониторинг TLS, проверка сертификатов и аудит массовых чтений/выгрузок |
| Медицинские данные: заболевания, жалобы/анамнез, заключения и  материалы<br/>В покое: медицинские записи в защищенном хранилище CRM, в Data Lake - только подготовленные наборы<br/> При передаче: пациент/врач - CRM, CRM - лабораторный API | Раскрытие может причинить существенный вред пациенту| В покое: шифрование БД, документного хранилища и резервных копий <br/>При передаче: TLS<br/> Аналитика: минимизация набора и обезличивание/псевдонимизация до Data Lake <br/>Контроль: проверка схем и сканирование наборов на прямые идентификаторы перед публикацией. |
| Договор пациента В покое: защищенное документное хранилище, связанное с CRM <br/>При передаче: портал/CRM | Договор может содержать идентификаторы и сведения об оказанной услуге | В покое: шифрование документного хранилища и резервных копий<br/> При передаче: <br/>TLS  <br/>Контроль: проверка шифрования хранилища и лшогирование чтения/выгрузки документов. |
| Направления и результаты анализов: идентификатор пациента/образца, назначенное исследование, результат<br/>В покое: результаты в хранилище CRM, для аналитики - только подготовленные данные в Data Lake. <br/>При передаче: CRM - лабораторный API - внешняя лаборатория, затем обратно. | Результат содержит медицинские сведения и при связи с идентификатором раскрывает личность пациента | В покое: шифрование CRM, хранилища документов и резервных копий<br/>При передаче: TLS, взаимная аутентификация для лабораторного соединения <br/>Контроль: мониторинг TLS, проверка сертификатов |
